# docme

Backendless React + Vite app built on [SELISE Blocks](https://api.seliseblocks.com).
Auth flows via the hosted OIDC SSO; data via the runtime GraphQL gateway.

## One-time setup (do these once)

### 1. Point the domain at your machine

Edit `C:\Windows\System32\drivers\etc\hosts` as Administrator and add:

```
127.0.0.1   dmqhre.slsblx.com
```

(Only on your machine — the public domain still resolves normally for everyone else.)

### 2. Generate a self-signed HTTPS cert

In Git Bash (or any shell with openssl):

```bash
mkdir -p .cert
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 365 \
  -keyout .cert/dev-key.pem \
  -out    .cert/dev-cert.pem \
  -subj "/CN=dmqhre.slsblx.com" \
  -addext "subjectAltName=DNS:dmqhre.slsblx.com"
```

### 3. Trust the cert (Windows, elevated PowerShell)

```powershell
Import-Certificate -FilePath ".\.cert\dev-cert.pem" -CertStoreLocation Cert:\CurrentUser\Root
```

Restart the browser for the trust to take effect.

### 4. Create the env files

```powershell
copy .env.example       .env
copy .env.local.example .env.local
```

Edit each and fill in the real values:

- **`.env`** → `BLOCKS_USERNAME` / `BLOCKS_PASSWORD` (your portal login).
- **`.env.local`** → `VITE_BLOCKS_PROJECT_KEY` (your `x-blocks-key`) + `VITE_BLOCKS_OIDC_CLIENT_ID`.

### 5. Install + run

```bash
npm install
npm run dev
```

Opens at `https://dmqhre.slsblx.com:5173` (HTTPS, on the project's real domain — required for the SSO cookie).

## What you get out of the box

| Route | Purpose |
|---|---|
| `/` | Home; shows login button or profile + logout depending on session |
| `/login` | Sign-in screen |
| `/callback` | The OIDC redirect URI — finalizes the session cookie |
| `/profile` | Raw `/iam/v4/iam/me` payload (for debugging) |
| `/docs` | List + create new Doc (data-gateway CRUD) |
| `/docs/:docId` | Read + mutate one Doc, its current DocVersion, and its Pages |

## Auth flow (verified)

1. Click **Sign in** → `GET /iam/v4/idp/initiate` → redirects browser to `iam.seliseblocks.com`.
2. Authenticate on the hosted login page.
3. IAM redirects back to `/callback?code=...&state=...`.
4. `GET /iam/v4/idp/callback` → sets the session cookie.
5. App calls `GET /iam/v4/iam/me` → 200 → user is signed in.
6. On 401 anywhere → `POST /iam/v4/oidc/token` (`grant_type=refresh_token`) → retry once.
7. Sign out → `POST /iam/v4/auth/Logout` (empty body, `credentials: include`) → server clears cookies.

## Data gateway (CRUD)

The runtime gateway lives at `POST {VITE_BLOCKS_API_URL}/data/v4/gateway` — one
endpoint, standard GraphQL body. Per the
**`blocks-data-gateway-crud`** skill, browser calls send `x-blocks-key:
VITE_BLOCKS_PROJECT_KEY` (the project's tenant id) plus `credentials: "include"`
so the signed-in user's SSO cookie travels with the request.

| Schema | Fields | Operations (auto-generated by the gateway) |
|---|---|---|
| `Doc` | `Name`, `Description`, `CurrentVersion` | `getDocs`, `insertDoc`, `updateDoc`, `deleteDoc` |
| `DocVersion` | `DocId`, `Version`, `Pages` (string[]), `IsPublished`, `IsActive` | `getDocVersions`, `insertDocVersion`, `updateDocVersion`, `deleteDocVersion` |
| `Page` | `Title`, `ContentType`, `Content` | `getPages`, `insertPage`, `updatePage`, `deletePage` |

(Plus the platform-managed fields on every record: `ItemId`, `CreatedDate`,
`CreatedBy`, `LastUpdatedDate`, `LastUpdatedBy`, `Language`, `OrganizationId`,
`Tags`.)

### Relationship model

```
Doc 1───1 DocVersion       (Doc.CurrentVersion = DocVersion.ItemId)
DocVersion 1───* Page      (DocVersion.Pages  = Page.ItemId[])
```

These are **field values, not GraphQL relations** — there's no automatic
expansion from Doc to its Pages. The detail page resolves them by reading
the DocVersion's `Pages` array (string[] of Page ItemIds) and then
fetching those Page records.

### Trying it

After signing in:

1. Click **Docs** on the home page.
2. Type a name and click **Create** → the Doc appears in the list.
3. Click **Open** on the new row → the detail page shows the empty Doc with
   a "Create first version" button..
4. Optionally set a **Version label** (e.g. `0.0.1`) and click **Create first
   version** → the Doc now points at a DocVersion (`CurrentVersion`).
5. Edit the **Version** label inline, and toggle **Draft/Published** +
   **Active/Inactive** on the DocVersion card.
6. Use **New version** to start another DocVersion — the Doc's
   `CurrentVersion` is repointed at it.
7. Fill in **Title** / **Content-Type** / **Content** (defaults to `md`) and
   click **Add page** → a Page is created and its `ItemId` is appended to
   the current DocVersion's `Pages` array.
8. Use **↑ / ↓** on any page to re-order it (the DocVersion's `Pages` array
   is rewritten in the new order).
9. **Delete** on a page → the Page record is deleted and its id is removed
   from the DocVersion's `Pages` array
If the gateway returns `Field 'X' does not exist on type 'Query'`, the
schema wasn't reloaded in the admin surface — go to the Blocks portal,
verify the schema, and run **Reload**. See the **`blocks-data-gateway-configuration`**
skill for that flow.

> If a future schema in the cloud uses an irregular plural, re-read
> `querySchema` and `mutationSchemas` from `GET /schemas` in the admin
> surface and override the `CrudNames` in `src/features/docs/api.ts`.

## Common gotchas

- **HTTP instead of HTTPS** → the session cookie is `Secure`, browser refuses to store it, login looks successful but every subsequent call 401s. Always run on `https://dmqhre.slsblx.com:5173`.
- **Wrong `VITE_BLOCKS_API_URL`** → cookie is scoped to `dmqhre.slsblx.com`, so the API must sit under the same registrable domain. Use `https://blocksapi.slsblx.com`, not `https://api.seliseblocks.com`.
- **`redirectUri` mismatch** → the value registered on the OIDC client must exactly equal `VITE_BLOCKS_REDIRECT_URI`. The local-dev URL has `:5173` in it; the prod URL doesn't.
- **No `Subject Alternative Name` in the cert** → modern browsers reject the cert. The `openssl` command above uses `-addext "subjectAltName=..."` to include the domain.
- **Committing `.env`** → add the `.env` line to `.gitignore` (already there) and never paste secrets into the chat.
- **`Field 'getDocs' does not exist on type 'Query'`** → the `Doc` schema
  hasn't been reloaded in the portal. Re-run **Reload** in the data
  service admin surface (see `blocks-data-gateway-configuration` skill).
